# 模型配置与路由

模型路由器分开配置上游端点、模型和单独的群聊配置。首次配置按下面的步骤添加聊天模型，再按需设置群特殊配置。

## 三层配置

| 配置              | 内容                                         | 范围             |
| ----------------- | -------------------------------------------- | ---------------- |
| 供应商 / Endpoint | API 基地址、凭据来源、启用状态               | 所有实例共享     |
| Model             | Endpoint、上游模型名、显示名与能力标签       | 所有实例共享     |
| Binding           | 为不同职责选择单独 Model、跟随主对话或停用 | 实例默认与群覆盖 |

## 配置第一个模型 {#添加供应商与模型}

先从模型服务提供方获取 OpenAI 兼容 API 基地址、API 密钥和实际接受的上游模型名。无鉴权服务可以留空密钥。模型调用可能产生费用，包括「直接对话」中的测试请求。

界面修改先进入草稿，点击发布后生效。重置草稿会丢弃模型配置所有页面尚未发布的修改。

1. 在「实例管理」选择要配置的实例，打开「模型路由器」，添加 Endpoint，输入显示名称和 API 基地址。
2. 选择凭据来源并配置密钥；无鉴权服务可使用空 Key。
3. 添加 Model，选择所属 Endpoint，填写服务实际接受的上游模型名。
4. 按模型实际能力配置标签，测试请求。
5. 在「实例默认路由」为「主对话」选择模型，点击「发布」。后续可按需开启 Embedding 等扩展。

API 基地址会与 `chat/completions` 拼接。例如服务接口是 `https://api.example.com/v1/chat/completions`，基地址填写 `https://api.example.com/v1`。界面的「获取名称」依赖上游 `/models` 路径提供模型列表，也可以手动填写模型名。

## 验证与更换模型

回到「概览」启用实例，进入「直接对话」，选择协议和私聊场景，连接后发送问候。收到回复后即可接入真实聊天平台。遇到问题见[故障排查](../operations/troubleshooting#模型和工具)。

为当前 Bot 更换模型时，修改当前实例的「主对话」绑定并发布；修改共享供应商的地址或密钥会影响其他实例。备份还原后需重新检查凭据，来源规则见下方[凭据来源](#凭据来源)。

## 职责

| 界面名称       | 键               | 作用                           |
| -------------- | ---------------- | ------------------------------ |
| 主对话         | `dialogue`       | 聊天与主工具循环               |
| 子 Agent       | `subagent`       | 委派子任务                     |
| 多模态（图片） | `vision`         | 图片描述与理解                 |
| 反思           | `reflection`     | 记忆反思、安全网关使用的路由   |
| 记忆提取       | `memory_extract` | 从对话或群压缩结果提取长期记忆 |
| 群聊压缩       | `group_compact`  | 群聊滚动摘要与上下文压缩       |
| Embedding      | `embedding`      | 记忆向量索引与语义检索         |

当前提供以上七类工作负载；Embedding 按[语义检索指南](./embedding)配置，不能用普通聊天模型路由替代。

使用界面提供的绑定模式：指定模型、跟随主对话、群级继承实例默认、或停用。主对话不能跟随自身；反思路由不提供停用选项。其他 Workload 停用后，相应功能会拒绝或跳过执行。图片模型必须实际支持图片输入；工具调用能力也需要上游和模型支持。

Embedding 模型需要实际支持 OpenAI 兼容 `/embeddings` 接口，标记 `embedding` 能力并单独绑定。实例默认路由可以指定模型或停用；群级可以继承默认或指定模型，不能选择停用或「跟随主对话」。实例还需开启 `ENABLE_EMBEDDING` 才使用向量检索。模型的「最大输入 Tokens」可选，用于约束记忆处理请求的输入副本，完整存储原文不受截断影响。

## 群级覆盖

进入「群级覆盖」，按规范化平台与群 ID 配置差异。未覆盖的工作负载继承当前实例默认值，私聊使用实例默认路由。QQ 的 OneBot 与 AstrBot aiocqhttp 接入归一化为 `qq` 平台，群号需填写同一个实际群 ID。群会话的模型配置面板会保留模型选择和操作入口。

## 凭据来源

当前 SQL 模式支持手动输入、Secret 文件和 Windows Credential Manager，禁止供应商使用进程环境变量（`env`）作为凭据来源。文件来源需要服务账号能够读取文件，Windows 凭据来源需要同一运行账号访问凭据。

手动密钥保存在数据库的凭据存储中。Web DTO 展示配置状态，应用层备份会置空密钥和凭据来源；迁移后需要检查并重新设置。共享凭据的修改影响所有使用对应 Endpoint 的实例。
