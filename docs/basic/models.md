# 配置第一个模型

本页带你让当前实例使用一个可用的聊天模型。多任务分工、群级覆盖和凭据来源的完整规则，见进阶篇[模型路由与群级覆盖](../usage/model-router)。

## 准备连接信息

从模型服务提供方获取以下信息。服务必须提供 OpenAI 兼容接口；工具调用和图片输入还需要模型实际支持，不能只靠勾选能力标签。

| 信息 | 填写方式 |
| --- | --- |
| API 基地址 | 例如 `https://api.example.com/v1`，不要填完整的 `chat/completions` 地址 |
| API 密钥 | 服务提供方生成的密钥；无鉴权的服务可以留空 |
| 模型名 | 服务实际接受的上游模型名，不是自己起的显示名称 |

模型调用可能产生费用，包括「直接对话」中的测试请求。不要把密钥粘贴到聊天记录、截图或问题报告里。

## 1. 添加供应商

1. 在「实例管理」选择要配置的实例，打开「模型路由器」。
2. 添加供应商（Endpoint），填写便于识别的显示名称和 API 基地址。
3. 选择手动输入凭据并填写密钥；需要文件或 Windows 凭据来源时，查看[完整说明](../usage/model-router#凭据来源)。

供应商和模型目录由所有实例共享。修改已有供应商的地址或密钥，会影响其他使用它的实例；仅为当前 Bot 更换模型时，优先调整实例路由。

## 2. 添加并选择模型

1. 添加模型（Model），选择刚刚配置的供应商。
2. 填写上游模型名，按实际支持情况设置能力标签，并测试请求。
3. 在「实例默认路由」中，为「主对话」指定该模型。
4. 点击「发布」。页面内的修改先进入草稿，不发布不会生效。

「获取名称」依赖供应商的模型列表接口；获取失败时，可以按供应商文档手动填写模型名。其他任务可以按能力复用同一个模型，首次试聊不需要同时开启 Embedding 等扩展。

## 3. 验证一次回复

回到「概览」启用实例，再进入「直接对话」，选择协议和私聊场景，连接后发送一条问候。收到回复后，再接入真实聊天平台。

如果没有回复，先检查实例是否启用、路由是否发布，以及供应商 / 模型是否启用。鉴权失败检查密钥；404 检查 API 基地址；模型不存在时检查上游模型名。更多问题见[故障排查](../operations/troubleshooting#模型和工具)。

## 更换模型与继续配置

更换聊天模型时，修改当前实例的「主对话」绑定并发布。配置人格不需要修改模型名，去[人格设定](../usage/persona)编辑系统提示词和示例对话即可。

需要图片理解、反思、群聊压缩或不同群使用不同模型时，继续阅读[模型路由与群级覆盖](../usage/model-router)。备份还原后，密钥与凭据来源需要重新检查和配置。
